# Лабараторная работа № 2
## Тема проекта: Космос и астрофизика 13 (Экзопланеты и телескопы)

- **Цель работы**: разработка структуры базы данных и ее подключение к бэкенду
- **Порядок показа**: **Скриншоты 1-2** показать панель администратора `adminer`, в которой логически удалить через статус `услугу`, посмотреть данные через `select` в БД. **Скриншоты 3-10** Показать 3 страницы приложения: выполнить поиск, удалить услугу, перейти по `url` удаленной `услуги`, добавить услугу, показать `select` в БД, опубликовать карточку, снова показать `select` в БД. **Скриншоты 11-13** В БД изменить поля по теме в `услуге` и количество строк в `м-м` и показать их в приложении. **Скриншоты 14-21** В коде показать модели, 5 контроллеров через `ORM`, а удаление услуги через `SQL UPDATE`. **Скриншот 22** Фото и видео по-умолчанию в `HTML`
- **Контрольные вопросы**: виды БД, SQL запросы, курсоры, ORM, модель и миграции, чистая архитектура
- **ER диаграмма**: сделать в StarUML; таблицы, связи, столбцы, типы столбцов и их длина, первичные, внешние ключи
- **Задание**: Создание базы данных `PostgreSQL` по теме работы, подключение БД к созданным трем шаблонам

Необходимо разработать структуру БД по выбранной теме и ее реализовать с учетом требований ниже. Использовать таблицу `услуг` в страницах разработанного приложения. Наполнить таблицы БД данными через `Adminer`.

Получение и поиск `услуг`, создание и публикация `услуг` (смена статуса) сделать через `ORM`. Для страницы `плитки` добавить кнопку логического удаления `услуги` (статус меняется на удален) с помощью выполнения SQL запроса `UPDATE`, без ORM. Всего шесть HTTP методов: три GET, один POST добавления новой карточки через `ORM`, второй POST публикации карточки через `ORM`, еще один POST для удаления услуги через `SQL курсор`. При получении ленты от сервера БД должна возвращаться сразу только одна строка, не нужно выполнять фильтрацию в коде через массивы и тд.

Для создания нужно указать название, фото, видео, нажать кнопку `Далее`. Для публикации нужно заполнить краткую информацию, оба поля по теме и нажать кнопку `Опубликовать`. При отстутствии `услуги` в статусе черновик у пользователя, она создается только при нажатии кнопки `Далее` на странице `добавление`. Если такая `услуга` уже есть, то страница открывается с заполненными полями и кнопкой `Опубликовать`. Новые фото и видел в этой лабораторной **не сохраняются** в БД и не передаются на сервер. Если в таблице пустые поля для `url` или файлы по ссылкам недоступны, то отображаются фото и видео по умолчанию, которые хранятся вместе с иконками на `SSR` сервере (они же отображаются на всех `страницах` для всех новых `карточек`). Удаленные услуги просматривать нельзя. Ставить `лайки` во второй лабораторной НЕ нужно, только отображать из БД.

**Требования к БД**:

Обязательно наличие 3 таблиц (каскадное удаление запрещено!):
* `услуг` (наименование, краткое описание, статус черновик/опубликован/удален, url к изображению, url к видео, два поля по предметной области, `дата создания` datetime, `создатель`; `дата формирования` datetime)
* `лайки` м-м пользователь-услуги (первичный и два внешних ключа)
* `пользователей`

Обязательно наличие 3 `услуг`: черновик, удалён, опубликован. У каждого пользователя не более одной `услуги` в статусе `черновик`. Названия таблиц и их полей должны соответствовать предметной области.

## Описание REST API методов

### Домен телескоп

| # Метода | Название HTTP метода | URL эндпоинт | Тело запроса | HTTP код | Описание |
| --- | --- | --- | --- | --- | --- |
| 1 | GET | `/api/telescopes?min=-90&max=90` | — | 200 OK | Список опубликованных телескопов с фильтром широты. |
| 2 | GET | `/api/telescopes/feed?id=1&next=true` | — | 200 OK | Получение первой, указанной или следующей карточки ленты. |
| 3 | GET | `/api/telescopes/draft` | — | 200 OK | Получение черновика текущего пользователя. |
| 4 | POST | `/api/telescopes` | `multipart/form-data`: `title`; необязательные файлы `image`, `video` | 201 Created | Создание черновика с загрузкой медиа в MinIO. |
| 5 | PUT | `/api/telescopes/:id` | JSON: `{"description":"Описание телескопа","latitude":38.5,"longitude":12.4}` | 200 OK | Публикация своего черновика. |
| 6 | DELETE | `/api/telescopes/:id` | — | 200 OK | Логическое удаление своей карточки. |
| 7 | POST | `/api/telescopes/:id/likes` | JSON: `{"like":1}` или `{"like":0}` | 200 OK | Установка или отмена лайка текущего пользователя. |

Параметры `min`, `max`, `id` и `next` передаются в URL и необязательны; `next` используется только вместе с `id`. Без `id` лента возвращает первую карточку, с `id` — указанную, с `id` и `next=true` — следующую.
